A full de-barrel is infeasible (`board.d.mts`/the `Canvas` god-object references `foundry.canvas.*` pervasively). **The fix (decided with maintainer):** the mixin file `placeables/mixins/shapes.d.mts` now ALSO exports `declare abstract class ShapePlaceableObject<Doc> extends PlaceableObject<Doc>` (the mixin instance modeled as a concrete subclass; members mirror the kept-for-fidelity `ShapeObject` + `ShapeObjectMixin` function, which the 5.6d test still uses). **Shape placeables `extends ShapePlaceableObject<Doc>` — a LAZY direct-generic heritage (like every other placeable's `extends PlaceableObject<Doc>`), so no eager eval, no cycle.** **⚠ 5.6f's `ShapeLayerMixin(PlaceablesLayer)` will hit the identical problem → give it the same `ShapeLayerPlaceablesLayer<...>`-style intermediate.**

**Two tsc-bug workarounds (eslint-only; tsgo/tsc/test-types unaffected).** Type-aware ESLint runs the `tsc` API and hit `Debug Failure ... parameter should have errors when reporting errors` — a **spurious crash surfacing in an unrelated `DialogV2.input` overload** (`dialog.test-d.ts:133`), triggered by perturbation from the new types.
